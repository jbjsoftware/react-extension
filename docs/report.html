Parallel Agents For Codebase-Wide Refactors
Large migrations — strict TypeScript mode, a CSS design-token overhaul, a JSON schema version bump — can be split into independent slices and worked by several subagents at once, each in its own context window. One agent maps the blast radius, others execute their slices in parallel, and a final reviewer agent reconciles conflicts and verifies the whole build. What used to be a multi-day grind collapses into a single supervised session.
Getting started: Ask Claude to plan the refactor and shard it, then spawn subagents per shard with the Task tool; use git worktrees so parallel work never collides. Finish with a dedicated review agent that reads only the combined diff.
Paste into Claude Code:
I want to do a codebase-wide refactor: [describe it, e.g. enable TypeScript strict mode / migrate CSS to design tokens / bump our JSON config schema to v2]. Phase 1 — Plan: Analyze the repo and produce a migration plan that shards the work into 3-5 independent slices with minimal overlap. List which files belong to each slice and any shared files that must be changed first. Phase 2 — Shared foundation: Make the shared/base changes yourself and verify the build still works. Phase 3 — Parallel execution: Launch a subagent per slice. Give each one its exact file list, the conventions to follow, and the command to verify its slice. They should not touch files outside their slice. Phase 4 — Reconcile: Once all subagents finish, run the full test suite and type check, resolve any conflicts or inconsistencies, and launch a fresh reviewer subagent that reads the complete diff with no prior context and flags anything sloppy, unsafe, or inconsistent. Report progress after each phase.
